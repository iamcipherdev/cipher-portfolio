// 04 — How I work

Build. Run. Test. Break. Fix.

AI writes code fast — including fast mistakes. My process exists to catch them before a client or a user does.

Step 01

Understand first

What is this for, who uses it, and what does success look like in numbers? No code until those three have answers.

Step 02

Build the whole path

A thin version that works end to end beats a thick one that works in pieces. Ship the path, then widen it.

Step 03

Test it, then break it

Run every main flow, then attack the edges — empty inputs, bad networks, the wrong button. Fix root causes, not symptoms.

Step 04

Ship & stand behind it

Deploy, verify on the live address, and stay reachable. My name is on the work; the work has to hold.
